# Meridian Casualty case — Econ Week 2026

## What this repo is
Team case-competition analysis for "Hiring Is Broken — Can You Fix It?". The case prompt is
`prompt.pdf` (read it first, every session). Raw data are in `meridian-case-data/` and are
READ-ONLY: never modify, overwrite, or add files there. `DATA-DICTIONARY.md` and `starter.py`
in that folder were written by an earlier AI session, not by the competition organisers;
`starter.load()` is correct and is the only way we load and join data.

## Deliverables (from the prompt)
(a) a judgment on the hiring process (what works, where it fails);
(b) whether the situational section (essay) still works as a screen and HOW WE KNOW — which
comparison, on whom, and what would have to be true for it to mean what we say;
(c) ONE costed recommendation (do nothing / applicants bear it / Meridian bears it / bear it
after hiring) against the status quo, plus what would have to be different to recommend
something else.
Format: four pages of narrative maximum, unlimited appendix of exhibits. Lead with the
recommendation. Report defended RANGES, never a lone point estimate. Name the hole in the
analysis. Every number in the text must point to an exhibit id in the appendix.

## Plan of record
`PLAN.md` at the repo root lists hypotheses H0–H12, each with sample, spec, exhibit id, and the
result that would falsify it. Execute one hypothesis per invocation. Do not invent new
deliverables: robustness work serves the three answers, it is not a fourth answer.

## Layout
- `analysis/` numbered scripts run in order (`00_load.py` … `08_cost_worksheet.py`);
  `analysis/utils.py` holds shared filters, the regression helper, and figure/table writers
- `build/` intermediate frames (disposable, regenerated by `00_load.py`)
- `outputs/exhibits/` PNG figures named `E##_short_name.png`
- `outputs/tables/` `E##_short_name.md` plus `.csv`
- `outputs/RESULTS.md` append-only log: every estimate with exhibit id, sample n, spec, SE type,
  and a one-line verdict against the falsification criterion in PLAN.md
- `report/narrative_outline.md` the four-page structure with exhibit references
- `.claude/skills/` project skills: `regression-table`, `cost-worksheet`, `exhibit`, `case-writing`

## Non-negotiable analysis rules
- ATS regime = the ATS in the APPLICATION month (`ats_at_application` from `starter.load()`),
  never the start month. The essay was written at application time.
- Three regimes: `legacy`, `new_pre` (new ATS, application before the AI-era cutoff),
  `new_post` (new ATS, application at or after the cutoff). Cutoff defaults to 2023-01 and is
  verified in E06; if changed, change it in `analysis/utils.py` only and re-run everything.
- Drop right-censored hires (`retained_6mo` is null). Never impute outcomes. State n after dropping.
- Flex placements are the sample NOT selected on the essay by Meridian; say so whenever used.
- Center fixed effects always; calendar-month fixed effects; cluster standard errors by center.
  Only 40 clusters: report a wild-cluster bootstrap p-value for headline interactions, or at
  minimum state the small-cluster caveat.
- Cost worksheet: implement exactly as written in the prompt. The worked example (r = 0.75,
  30 days to fill, 6 % reopen, 2025 average rates → about $26,103 hiring-plus-separation cost
  and about $11,800 quality cost) is the unit test and must pass before any costing is reported.
- Every figure: title, labelled axes with units, a one-line sample statement, a source note.
  Load the `dataviz` skill before writing any chart code.
- Never report a coefficient without n, SE type, confidence interval, and exhibit id.
- Migration was NOT random (pilot centers were the large ones with strong IT). Every causal
  claim states the identifying comparison and what would have to be true for it to hold.
- Numbers in prose come from `outputs/RESULTS.md`, never from memory of an earlier run.

## Workflow
- Python 3.14. Install once: `pip install pandas numpy statsmodels scipy matplotlib tabulate`
  (already installed on this machine as of 2026-09-12).
  `linearmodels` is optional; if it will not install, use statsmodels OLS with dummies and
  `cov_type="cluster"`.
- Run scripts as modules from the repo root: `python -m analysis.06_essay_validity`.
- Every script must regenerate its exhibits from raw data when re-run. No hand-edited outputs.
- After each script, append its findings to `outputs/RESULTS.md`.
- Do not start the narrative until H0–H12 all have entries in RESULTS.md.
- Use `/code-review` on `analysis/` before trusting numbers that go into the report.

## Writing rules for report text
- Plain English. Define any technical term in one line the first time it appears.
- Active voice. No hedging fog, but every estimate is a range with the reason it is a range.
- "We could not determine X" is required, not optional.
- Spell-check. Label every graph. Trace every claim to an exhibit id.
